- **Run.** Dev CI 41214973954 on `fe649360`: Linux 3.14 and Windows 3.14

  macOS: see U-20261101-02.
- **The failure.**
  `test_agent_dag_continuation.py::test_approval_transaction_rolls_back_all_bindings_and_adoptions`
  expected "database operation failed". It got a 409: "DAG continuation
  evidence or decisions changed; review again".

  (`0.01` for the timeout case).
- **Cost, measured.** The 19 test files that use the helper: 235 tests in
  113.0 s with 2 seconds, 99.3 s with 20 seconds. No test waits longer, because
  a healthy task returns as soon as it finishes.

## U-20261101-03 · 2026-11-01 · Bind this package's HTTP servers without a reverse lookup of their address · #incident #ci #macos #server

- **Run.** Dev CI 41256321097 on `e779af0c`, the first on macos-15. The
  macOS 3.10 square had 7 failures out of 16,405 tests, in a suite of 27:41.
  None was a TCC-gated test.
  - Six were child-process fixtures (`_transfer_process.py`) reporting "owned
    transfer startup exceeded its original budget" (10 seconds), then a failed
    shutdown.
  - One was the process-death test of `test_agent_dag_background_crash.py`.
  - Each took about 20.4 seconds: the startup budget plus the 10-second stop
    wait. In the parent process,
    `test_admin_client.py::test_add_host_round_trip` took 35.6 seconds on
    macos-15 and 1.0 on macos-14. The tests after it in the file, starting the
    same two servers, took about 1 second each.
- **Measured.** A throwaway branch (`diag/macos15-startup`, deleted after the
  run) timed it on both images (run 41258738137, Python 3.10):

  | | macos-15 | macos-14 |
  |---|---:|---:|
  | first `socket.getfqdn('127.0.0.1')` in a process | 35.03 s | 0.005 s |
  | second one in the same process | 0.002 s | 0.000 s |
  | a fresh child process doing the same | 35.04 s, 35.01 s | 0.11 s total |

  `HTTPServer.server_bind` sets `server_name = socket.getfqdn(host)`. On
  macos-15 every process therefore paid 35 seconds the first time any of its
  HTTP servers bound.
- **Fix.** New `LocalThreadingHTTPServer` in `utils/http_headers.py`. Its
  `server_bind` records the bound host as `server_name` instead of resolving
  it; nothing in the package reads `server_name`. Every HTTP server in the
  package now uses it:
  - `RestApiServer`
  - `_MCPHttpServer`
  - `PrometheusExporter`
  - `HttpChallengeServer`
  - `WebhookTriggerServer`

  That also helps a deployment whose reverse DNS times out.
- **Guard.** `test_http_server_bind.py` starts the REST, exporter, challenge
  and webhook servers with `socket.getfqdn` patched to raise, and checks that
  the MCP server class is a `LocalThreadingHTTPServer`. An AST scan fails on
  any other module that constructs or subclasses a stock
  `HTTPServer`/`ThreadingHTTPServer`. It flags the pre-fix `rest_server.py`,
  `http_transport.py` and `exporter.py`.
- **Evidence.** 1,161 tests pass: the 71 REST, MCP, webhook, exporter, ACME,
  admin and trigger test files, plus the doc, complexity and cross-project
  contract gates. ruff reports nothing. `import je_auto_control` still loads
  no PySide6.
- **Open items:** none.

## U-20261101-04 · 2026-11-01 · Widen the presence reader test's safety gate · #incident #agent #ci #test

- **Run.** Dev CI 41259682516 on `6faab853`. macOS 15 3.10 passed: the fix of

  and Windows 3.10 passed too. Windows 3.14 had 1 failure out of 16,617 tests,
  in a suite of 52:10.
- **The failure.**
  `test_agent_presence_reader.py::test_first_bind_blocks_are_bounded_and_late_replies_never_authorize[receive]`
  expected `close()` to refuse while the blocked receive was still in
  progress, and `close()` succeeded.
  - The harness's blocked stage waits on its gate for at most 2 seconds and
    then raises, which ends the blocked operation.
  - The test measures `ready()` (bounded at 0.7 s), a notice (0.3 s) and

  cleanup always opens it, so no test waits longer. The file's 34 tests run in
  8.1 s as before.
