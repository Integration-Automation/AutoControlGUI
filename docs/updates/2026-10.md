## U-20261001-01 · 2026-10-01 · Run AC_web_run's documented form, record WebRunner failures, gate through execute_one · #bugfix #webrunner

The AutoControl half of stages S0 and S1 of the two-way WebRunner bridge (WebRunner `progress.md` #20, workspace X-27). The WebRunner half, its public `execute_one`, is WebRunner U-20261001-26.

- **Documented form broken**: `["AC_web_run", {"action": "WR_to_url", "params": {...}}]`, the form in the bridge's docstring, bound `action` to the named parameter of `_ac_web_run`. The payload then lost its command name and every such call failed with "action name must start with WR_, got None". Only the positional-dict form had a test. `_ac_web_run` now rebuilds the payload from the keyword form.
- **One failure aborted the script**: WebRunner's and Selenium's exceptions are not `AutoControlException`s, so the executor did not contain them. `run_webrunner_action` now re-raises any non-AutoControl error from a `WR_*` command as `WebRunnerBridgeError`, with the error as its cause. AutoControl errors pass through unchanged.
- **Gates**: a command now runs through WebRunner's `execute_one` (refused commands, the arbitrary-script gate, retries, failure screenshots) when the installed WebRunner has it. Older releases fall back to the `event_dict` callable.
- **No import to probe**: `is_webrunner_available()` uses `importlib.util.find_spec`, so the GUI tab and `AC_web_available` no longer import WebRunner, which wrote `WEBRunner.log` into the cwd.
- **Docs and examples**:
  - the bridge docstring now uses `WR_to_url` (it named a nonexistent `WR_get_url`) and `webdriver_name` (not `browser`);
  - the example clicks with `WR_find_element_by` + `WR_element_click` (it passed a CSS selector as `WR_left_click`'s recorded `element_name`);
  - the "~440 commands" counts are gone from the GUI tab, an MCP tool description and the example.
- **Script Builder**: a "Browser" category with the eight `AC_web_*` commands.
- **Tests**:
  - `test_webrunner_bridge.py` gained 7 tests: the keyword form through the executor and a recorded non-fatal failure (both failed before the fix), plus wrapping, AutoControl errors passing through, the `execute_one` path, no import on probe, and a WebRunner without `execute_one`. An autouse fixture keeps the fake-executor tests off a real `execute_one`.
  - New `test_webrunner_contract.py` (3 tests) checks the real package and skips where it is not installed. It passed against the WebRunner working tree (37 passed with the bridge tests, run on an interpreter that has both).
- **Other direction**: WebRunner's new `WR_ac_*` commands (its U-20261001-27) run AutoControl actions through `executor.execute_action(actions, raise_on_error=True)` and refuse `AC_shell_command`, `AC_execute_process`, `AC_add_package_*`, `AC_execute_action`, `AC_execute_files`, `AC_run_agent` and `AC_web_*` by name. `test_cross_project_contracts.py` gained two tests pinning that API and those names, and §6 has a WebRunner row.
- **Sweep fixes**: `_ac_web_run_actions` is annotated `List[Dict[str, Any]]` (a bare `list` read as an unfielded scalar once the Script Builder listed the command). `test_utils_sweep_audit.py` expected a command's own `TypeError` to escape as `TypeError`; it now arrives as `WebRunnerBridgeError` with that cause, still not reported as a parameter mismatch.
